# 顺丰物流接入 - 需求文档

> 版本：v1.1 | 日期：2026-06-17 | 状态：已确认

---

## 一、背景与目标

当前 AI发货总表中的「快递公司」「快递单号」由人工填写，发货后无法自动追踪物流状态。公司已有顺丰开发者月结账户，可通过 API 下单、获取单号、查询物流轨迹。

**目标**：将顺丰月结账户的订单物流能力接入飞书统计，实现发货总表的快递公司、快递单号、物流状态三个字段的自动化写入与更新。

**下单模式说明**：本系统采用 **API 自动下单模式**。用户在发货管理界面确认发货后，系统调用顺丰丰桥 API 创建运单并自动回填单号，不依赖人工在微信小程序手动寄件。如有少数场景需要手动寄件后补录，通过「手动录入单号」功能兜底。

## 三、地址匹配与合同关联

### 3.1 发货地址结构

收件地址中的项目名称用中文全角括号包裹，格式：

```
{收件人}，{收件电话}，{省市区街道详细地址}【{项目名称}】
```

例：`张三，13812345678，盐城市大丰区丰华街道XX路XX号【城市花园二期消防远程控制项目】`

> **符号选型说明**：选用中文方头括号 `【】`，因为真实地址中不会出现，不与地址自带的 `（）` 产生歧义。

> **注意**：收件人姓名和电话为顺丰下单接口必填项，需从 AI 发货总表中读取。

### 3.2 项目名称提取规则

从顺丰订单的收件地址中提取括号内文本作为项目名称，与 AI发货总表的「项目名称」字段匹配：

- **精确匹配**：地址中 `【XXX】` 提取后与发货总表项目名称**完全相等** → 直接关联
- **模糊匹配**（兜底，当精确匹配失败时）：提取文本与项目名双向包含判断 → 标记「待确认」，人工确认后生效

### 3.3 特殊地址与兜底

以下情况视为非标准匹配，系统**不自动关联**，需人工介入：

- 地址中**无【】标识**或【】内为空
- 括号提取出的文本与发货总表中**所有项目名均不匹配**（精确+模糊都失败）
- 人工手动寄件后补录单号的场景

处理方式：人工在发货总表「备注」字段标注运单号，系统在物流轮询时读取备注中的单号进行轨迹查询，但不做项目名匹配。

## 四、顺丰API对接

### 4.1 涉及的顺丰接口

| 接口 | 用途 | 调用时机 |
|------|------|---------|
| 下单接口（EXP_RECE_CREATE_ORDER） | 创建顺丰运单，返回运单号 | 人工在界面点击「发货」时 |
| 路由查询（EXP_RECE_SEARCH_ROUTES） | 按运单号查询全量物流轨迹节点 | 定时轮询，逐个运单查询 |
| 订单结果查询（EXP_RECE_QUERY_ORDER） | 查询订单状态，验证下单结果 | 下单后立即调用一次确认 |

> **说明**：EXP_RECE_SEARCH_ROUTES 为单运单号查询接口（非批量），每次查询一个运单号。日均 50-100 单规模下逐个查询可行；若未来运单量增长，可考虑路由订阅推送方式（EXP_RECE_REGISTER_ROUTE 回调）。

### 4.2 认证方式

顺丰丰桥使用 **MD5 签名认证**，基于 `partnerID` + `checkWord` 生成签名字段 `msgDigest`：

```
msgDigest = Base64(MD5(URLEncode(msgData + timestamp + checkWord)))
```

凭证存储在 `.env` 文件中：

```env
SF_PARTNER_ID=xxx            # 顾客编码（clientCode）
SF_CHECKWORD=xxx             # 校验码
SF_MONTHLY_CARD=xxx          # 月结卡号
SF_SERVER_URL=https://sfapi.sf-express.com       # 生产环境
SF_SERVER_URL_SBOX=https://sfapi-sbox.sf-express.com  # 沙箱环境（测试用）
```

### 4.3 下单流程

```
人工确认发货 → 触发下单
     │
     ├── 1. 校验：该合同是否已有快递单号？有则跳过（防重复下单）
     ├── 2. 从发货总表读取：项目名称、收件人、收件电话
     ├── 3. 构建收件地址：{收件人}，{收件电话}，{省市区详细地址}【{项目名称}】
     ├── 4. 调用顺丰下单接口（EXP_RECE_CREATE_ORDER）
     ├── 5. 下单成功 → 回写快递公司=顺丰速运、快递单号、物流状态=待揽收
     └── 6. 下单失败 → 提示错误信息，不写入任何数据，允许重试
```

### 4.4 物流轨迹轮询

```
定时任务（每2小时，8:00-20:00）
     │
     ├── 1. 读取发货总表中「物流状态 ≠ 已签收 且 快递单号 ≠ 空」的所有行
     ├── 2. 逐条调用顺丰路由查询接口（EXP_RECE_SEARCH_ROUTES）
     ├── 3. 解析最新轨迹节点（opCode + 描述 + 时间）
     ├── 4. 更新：物流状态、物流详情、物流更新时间
     ├── 5. 若状态由「非签收」变为「已签收」→ 触发飞书群通知
     └── 6. 单条查询失败不阻断后续运单处理，记录错误日志
```

### 4.5 物流状态映射

顺丰路由查询返回 `opCode`（操作码），需映射为飞书展示状态：

| 顺丰操作码 (opCode) | 含义 | 飞书展示状态 |
|---------------------|------|------------|
| 50 | 已收件/揽收 | 待揽收（注：表示快递员已取件，运单刚生成） |
| 30 | 运输中/中转 | 运输中 |
| 44 | 派送中 | 派送中 |
| 80 | 已签收 | 已签收 |
| 其他（如 99=异常、92=退件） | 异常件 | 异常 |

> **注意**：上述 opCode 为常见值，正式对接时以顺丰丰桥 API 文档中的实际操作码为准。状态映射表应配置化，便于后续调整。

## 五、界面设计

### 5.1 发货管理页面

新增独立页面，路径：`/shipping`

界面元素：
- **待发货合同列表**：显示「是否发货 = 是」但「快递单号 = 空」的合同
- **「一键下单」按钮**：对选中的合同批量调用顺丰下单接口
- **「手动录入单号」入口**：针对人工寄件后补录的场景，填入项目名+单号
- **「刷新物流状态」按钮**：手动触发全量物流轨迹查询
- **物流状态总览卡片**：各状态运单数量统计（待揽收/运输中/派送中/已签收/异常）

### 5.2 发货总表视图增强

在飞书多维表格中，为「物流状态」字段配置**条件颜色**：
- 待揽收 → 灰色
- 运输中 → 蓝色
- 派送中 → 橙色
- 已签收 → 绿色
- 异常 → 红色

## 七、定时任务

| 任务 | 频率 | 说明 |
|------|------|------|
| 物流轨迹刷新 | 每 2 小时（8:00-20:00） | 轮询未签收运单的最新轨迹 |
| 签收通知 | 每次刷新时检查 | 新签收的运单推送飞书群通知 |

> 顺丰 API 路由查询为单运单号查询，日均 50-100 单规模安全可控。每次轮询逐条调用，单条之间间隔 200ms 防止触发限频。

## 八、约束与规则汇总

| # | 规则 |
|---|------|
| 1 | **防重复下单**：下单前检查该合同是否已有快递单号，有则跳过；此检查同时拦截 API 下单和人工手动录入冲突 |
| 2 | **人工已填写不覆盖**：若发货总表中某个合同的「快递公司」「快递单号」已有人工填写且物流轮询任务尚未覆盖，系统不覆盖（保护人工先于系统写入的数据） |
| 3 | 物流状态、物流更新时间、物流详情仅由定时轮询更新，不参与下单流程 |
| 4 | 项目名称从地址【 】方头括号内提取，匹配失败则跳过自动关联，需人工在备注标注 |
| 5 | 顺丰 API 凭证从 `.env` 读取，不硬编码 |
| 6 | 物流状态 = 已签收的运单不再参与轮询 |
| 7 | 收件地址格式固定：`收件人，收件电话，省市区详细地址【项目名称】`——项目标识使用中文方头括号 `【】` |
| 8 | 运单查询失败不阻断其他运单处理，逐条容错并记录错误日志 |
| 9 | 顺丰月结账户的月结卡号用于运费结算，下单时必须传入 |
| 10 | 下单失败时，不写入快递单号字段，允许用户重新触发下单 |

## 九、错误处理与容错

### 9.1 顺丰 API 异常处理

| 场景 | 处理策略 |
|------|---------|
| API 超时（>5s） | 重试 2 次，间隔 1s，均失败则提示用户「顺丰接口暂时不可用，请稍后重试」 |
| API 返回业务错误（如地址格式错误） | 不重试，直接提示具体错误原因，需人工修正后重新触发 |
| 签名验证失败 | 检查 `partnerID/checkWord` 配置，提示配置错误 |
| 月结卡号无效 | 提示用户联系顺丰确认月结账户状态 |

### 9.2 下单成功但飞书写入失败

```
下单成功（已生成运单号）→ 飞书写入失败
```
此时运单号已存在但未写入发货总表，造成数据丢失风险。

**补偿机制**：
- 下单接口返回运单号后，先写入本地日志文件（含合同编号+运单号+时间戳）
- 再写入飞书发货总表
- 若飞书写入失败，定时任务下次扫描日志文件进行补偿回写

### 9.3 日志要求

| 日志内容 | 级别 | 用途 |
|---------|------|------|
| 下单请求/响应 | INFO | 追踪接口调用 |
| 下单失败 | ERROR | 人工排查 |
| 物流状态变更（非签收→签收） | INFO | 触发通知 |
| 飞书写入失败 | ERROR | 触发补偿 |
| 轮询任务开始/结束/耗时 | INFO | 监控健康度 |
