# 飞书三线通知卡片重设计方案

> **设计目标**：更美观、规范、符合大公司管理需求、每个卡片精准服务目标受众
>
> **设计阶段**：提案阶段（等待多路 AI 评审后实施）

---

## 一、现状分析

### 当前三线卡片架构

| 轨道 | 卡片函数 | 目标受众 | 触发条件 | 当前头色 |
|------|---------|---------|---------|---------|
| Track 1 | `_build_procurement_card` | 采购/产协群 | 缺货SKU > 0 | Red / Orange |
| Track 2 | `_build_planner_card` | 排单员个人通知 | 始终触发 | Blue |
| Track 3 | `_build_boss_card` | 领导层/经营群 | 始终触发 | Red/Yellow/Green |
| - | `_send_personal_notification` | 排单员私聊 | 始终触发 | Blue |

### 当前设计问题诊断（按 impeccable 标准）

#### 问题 1：视觉层次混乱

- 三张卡片都使用**相同的信息密度模板**（标题 → 正文 → 分隔线 → 按钮），缺乏层次差异化
- 卡片内元素排列以纯文本 markdown 堆砌为主，没有视觉节奏
- **违反 impeccable DO**：万物皆卡片 / 卡片套卡片

#### 问题 2：信息过载与冗余

- Track 1 用一大段文本描述"发现 3 项物料处于断供状态"，但不直观展示关键数字
- Track 2 只有"已排单/未排单"两个数字，但排单员还需要更多上下文决策
- Track 3 是大段文字 + 数据混排，领导很难 3 秒内抓住重点

#### 问题 3：emoji 滥用（违反 impeccable 铁律）

```python
"🚨 核心物料断供阻断预警！(级别：高)"
"🧨 最紧急物料特写"
"📦 履约与资产盘面"
"💥 爆炸半径："
```

- 多达 15+ 个不同 emoji，削弱专业感
- **impeccable 铁律**：不使用 emoji，改用图标系统或排版层次

#### 问题 4：颜色语义不统一

- 红色同时用于"阻断"和"警告"场景
- 不同卡片间颜色语言不一致
- **建议**：建立统一的语义色板

#### 问题 5：交互能力弱

- 当前只有 1 个按钮（部分场景 0 个）
- 缺乏快速操作入口（查看详情、一键跳转、归档标记）
- 卡片是"看完就过"的信息，而非"可操作的工单"

## 二、设计方案

### 2.1 全局设计规范

#### 视觉色板（企业级供应链场景）

| 语义 | 色值 | 用途 |
|------|------|------|
| **阻断 / 严重** | `#A32D2D`（c-red 800） | 缺货阻断交付、SLA超期 |
| **警告 / 关注** | `#EF9F27`（c-amber 300） | 预警库存、产能紧张 |
| **正常 / 通过** | `#3B6D11`（c-green 800） | 交付正常、库存充足 |
| **信息 / 操作** | `#185FA5`（c-blue 800） | 确认通知、数据链接 |
| **中性 / 背景** | `#F1EFE8`（c-gray 50） | 二级信息区域 |

#### 排版层次

- **卡片标题**：无 emoji，使用左侧色条（6px wide bar）+ 简洁标题
- **数字指标**：大字号 + 语义色 + 紧凑标签，采用 `grid` 布局
- **关键信息**：使用 `background: var(--color-background-secondary)` 高亮区域
- **操作区**：最多 2 个按钮，primary + default 搭配

#### 统一头色规则

```
缺货 > 0 → red
延迟 > 0 → yellow
正常     → blue（排单确认流）/ green（大盘流）
```

### 2.2 各卡片设计方案

#### Card 1: 物料异常流（`_build_procurement_card`）

**目标受众**：采购负责人 + 生产协调群  
**场景**：有缺货物料时需要立即介入，更新交期或找替代料  
**设计语言**：红色阻断 + 数字仪表盘

**布局结构**：
```
┌─────────────────────────────────────┐
│ ▌ 物料断供阻断预警           [RUN-XX] │  ← 无emoji标题 + 批次标签
├─────────────────────────────────────┤
│  ┌────────┐ ┌────────┐ ┌────────┐   │
│  │   3    │ │  3天   │ │   高   │   │  ← 3格数字仪表盘
│  │断供物料│ │SLA剩余 │ │风险等级│   │
│  └────────┘ └────────┘ └────────┘   │
├─────────────────────────────────────┤
│  ■ 最紧急物料：SKU-1024             │  ← 高亮区域
│    影响项目：某高校智慧教室项目       │
│    SLA倒计时：剩余 3 天              │
├─────────────────────────────────────┤
│  其他断供：SKU-1025(缺50) │ SKU-... │  ← 紧凑列表
├─────────────────────────────────────┤
│  [更新交期]  [查看库存详情]          │  ← 双按钮操作区
└─────────────────────────────────────┘
```

**关键改进**：
1. 去掉所有 emoji，用数字仪表盘替代
2. 三格指标一目了然
3. 最紧急物料用高亮区块突出
4. 双按钮让采购可以直接操作

---

#### Card 2: 排单确认流（`_send_personal_notification` + `_build_planner_card`）

**目标受众**：排单员（个人私聊，非群消息）  
**场景**：AI 排单完成后需要人工确认  
**设计语言**：蓝色信息 + 双列指标 + 操作区

> **注意**：此卡片有一个独特场景——排单员需要看到**排单结果 + 审计结果 + 未来3天待发**在同一卡片内。当前 `_send_personal_notification` 用 markdown 堆积了大量信息，需要结构化。

**布局结构**：
```
┌─────────────────────────────────────┐
│ ▌ 排单任务确认              [RUN-XX] │
├─────────────────────────────────────┤
│  ┌──────────┐  ┌──────────┐         │
│  │    42    │  │    3     │         │  ← 双格指标
│  │  已排单  │  │  待确认  │         │
│  └──────────┘  └──────────┘         │
│                                      │
│  缺货合同 5 份 │ 未来3天应发 18 单    │  ← 辅助信息
├─────────────────────────────────────┤
│  ■ 未来3天待发项目                  │  ← 可折叠区域
│    6月21日：项目A、项目B等3个        │
│    6月22日：项目C、项目D             │
├─────────────────────────────────────┤
│  ■ 排单审计：通过 (4/4规则)          │  ← 审计摘要
│    抽查 5/61 合同，无异常            │
├─────────────────────────────────────┤
│  [查看排单总表]   [审计记录]         │
└─────────────────────────────────────┘
```

**改版策略**：
1. 将 `_send_personal_notification` 和 `_build_planner_card` **合并为一张卡片**（当前排单员收到 2 条通知过于碎片化）
2. 审计结果集成到卡片底部，不另起一行分隔线
3. 未来3天待发用紧凑列表展示

---

#### Card 3: 战略大盘流（`_build_boss_card`）

**目标受众**：管理层 / 经营决策群  
**场景**：每天查看经营健康度，快速判断是否需要介入  
**设计语言**：四格仪表盘 + AI 洞察摘要

**布局结构**：
```
┌─────────────────────────────────────┐
│ ▌ 供应链经营日报            [RUN-XX] │
├─────────────────────────────────────┤
│  交付率     库存健康率   延迟订单   产能池 │
│   84%        72%        7单      3.2天  │  ← 四列迷你指标
├─────────────────────────────────────┤
│  ■ AI 经营洞察                      │
│  可发38/45单，7单交付阻断；          │
│  断供物料3项，产能池仅够3天流转      │
├─────────────────────────────────────┤
│  [查看多维表格全局大盘]              │
└─────────────────────────────────────┘
```

**关键改进**：
1. 四格仪表盘让领导 3 秒看完全局
2. AI 洞察从啰嗦段落压缩为 2 句话
3. 去掉冗余的"履约与资产盘面"和"风险阻断区"独立区块，信息密度降低 40%
4. 底部 note 信息整合到指标区

## 三、实施计划

### 3.1 改动范围

| 文件 | 函数 | 改动内容 |
|------|------|---------|
| `ai_daily_agent.py` | `_build_procurement_card()` | 重写卡片结构，无emoji+数字仪表盘+高亮关键物料+双按钮 |
| `ai_daily_agent.py` | `_build_planner_card()` | 重写卡片结构，合并审计信息，双格指标 |
| `ai_daily_agent.py` | `_build_boss_card()` | 重写卡片结构，四格仪表盘+精简洞察 |
| `scheduler_api.py` | `_send_personal_notification()` | 重构为结构化卡片（非纯markdown），移除多余的审计分隔线 |

### 3.2 不需要改动的部分

- `_build_card_color()` — 颜色判定逻辑保留
- `_boss_ai_insight()` — AI 洞察生成逻辑保留
- `_procurement_owner_mention()` — @人逻辑保留
- `_send_card_to_webhook()` — 发送基础设施不碰
- `execute_triple_track_dispatch()` — 三线分流主控不碰

### 3.3 风险控制

- **不改变数据流**：仅重构卡片 UI 结构，不碰任何数据读取/计算逻辑
- **保留降级能力**：卡片发送失败不阻断排单主流程（现有行为）
- **分批实施**：先改 Track 2（影响最小，排单员个人），再改 Track 1 和 Track 3

## 四、与当前 UI Designer 专家角色的关联

本次重设计的飞书卡片本质上是**企业级信息卡片 UI**，需要遵循：

1. **视觉层次**：通过色条、数字大小、区块划分建立信息优先级
2. **色彩语义**：统一的阻断/警告/正常/信息色彩语言
3. **信息密度**：不同受众不同信息量（排单员需要细节，领导需要摘要）
4. **操作可达性**：每个卡片有 1-2 个明确的操作入口
