# 确认面板持久化方案

> 问题：当前 `/confirm` 页面依赖 localhost:8000 进程存活，sandbox 频繁杀掉进程导致页面不可用，且 localhost 排单员浏览器无法访问。

---

## 方案对比

| | A: 飞书多维表格自动化 | B: CloudStudio 部署 | C: 飞书机器人卡片交互 |
|---|---|---|---|
| 排单员操作 | 打开日报表 → 勾选复选框 | 打开网页 → 点按钮 | 飞书卡片内直接点按钮 |
| 依赖 | 飞书自动化规则 | CloudStudio 服务 | 飞书应用回调 |
| 稳定性 | 极高（飞书托管） | 高（云托管） | 高（飞书托管回调） |
| 实现周期 | 10分钟 | 30分钟 | 需要飞书应用审批 |

---

## 推荐方案 A：飞书多维表格自动化

### 原理

```
排单员打开飞书日报表 → 找到今天的行 → 勾选「确认推送」复选框
                                    ↓
                       飞书自动化检测到字段变更
                                    ↓
                        webhook POST → 调度器 → 群发通知
                                    ↓
                        回写「确认时间」「确认人」
```

### 需要的操作（5步，10分钟）

**Step 1**：日报表已有「确认状态」字段（fld4JVfd8y，单选：待确认/已确认），直接可用

**Step 2**：创建飞书自动化规则
- 触发：当「确认状态」变更为「已确认」
- 动作：发送 webhook POST 到调度器
- webhook URL：`http://调度器地址:8000/confirm_schedule?batch_id={{排单批次号}}`

**Step 3**：排单员操作流程
1. 打开飞书 → 多维表格 → AI排单日报
2. 找到最新一行（今天排的）
3. 把「确认状态」从「待确认」改成「已确认」
4. 自动化自动触发群通知

**Step 4**：飞书卡片中的「确认排单」按钮改为跳转到日报表对应行（替代 localhost URL）

**Step 5**：调度器 `/confirm_schedule` 端点已就绪（只需确保运行时可达）

### 优点
- 全程在飞书内完成，不需要浏览器
- 飞书自动化托管，99.9% 可用
- 排单员已在日报表上工作，无额外学习成本
- 零代码新增

### 缺点
- 调度器仍需运行（但不需要公网，内网即可）
- 自动化规则有 1-5 秒延迟

---

## 备选方案 B：CloudStudio 部署

### 原理
将当前 scheduler_api.py 部署到 CloudStudio 沙箱，获得一个持久公网 URL。

### 操作
1. 部署 `scheduler_api.py` 到 CloudStudio
2. 获得 `https://xxx.cloudstudio.net` 公网地址
3. 确认面板永久可访问
4. `SCHEDULER_HOST` 指向 CloudStudio 地址
5. 飞书卡片按钮指向 CloudStudio 的 `/confirm` 页面

### 优点
- 有持久公网 URL
- 排单员浏览器可以直接打开
- 面板不会因为本地进程被杀而消失

### 缺点
- 需要 CloudStudio 支持后台常驻进程
- 部署和维护成本较高

---

## 建议

**推荐方案 A**（飞书自动化），因为：
1. 日报表「确认状态」字段已在飞书上（刚才加的）
2. 排单员本来就要看日报表，改一下确认状态就行
3. 不需要部署任何新东西
4. 飞书自动化是原生能力，稳定可靠

唯一前提：调度器需要内网可达。如果调度器部署在服务器上（非本地），直接填内网 IP 即可。
