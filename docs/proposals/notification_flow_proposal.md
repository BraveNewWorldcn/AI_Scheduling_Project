## 二、改动 1：紧缺物料展示改造

### 当前

```
紧缺物料：全网行为管理-全网行为管理
```

只显示了1个产品的名称（且名称重复），没有数量，没有覆盖全貌。

### 目标

```
**缺货物料**：共 12 个SKU

网络行为管理    缺 34 个
下一代防火墙    缺 23 个  
交换机          缺 19 个
AI服务器        缺 15 个
存储设备        缺 8 个
+7 项详见排单总表
```

### 数据来源

数据从 `summary` DataFrame 提取：

| 字段 | 来源 | 说明 |
|------|------|------|
| `缺货SKU列表` | summary 每行 | 如 "SKU-A, SKU-B" |
| `缺货SKU数` | summary 每行 | 该合同的缺货SKU个数 |
| `订单总数量` | summary 每行 | 该合同的总订货数量 |
| `整体状态` | summary 每行 | 用于筛选缺货合同 |

聚合逻辑：
```
1. 筛选 summary[summary["整体状态"] == "缺货"]
2. 对每行解析 缺货SKU列表，提取每个SKU名称
3. 统计每个SKU的出现次数（作为"缺货合同数"或"缺口订单数"）
4. 按出现次数降序排列
5. Top 5 展示
6. 总数显示唯一SKU个数
```

### Non-goals（这个改动不做）

- ❌ 不展示每个缺货SKU影响的合同列表（那是采购卡片的事）
- ❌ 不做SKU编码→设备名称的翻译映射（直接用SKU名称）
- ❌ 不展示库存缺口数量（如"库存100，需求134，缺口34"）

## 三、改动 2：通知流程重构

### 当前流程（问题）

```
排单完成
  ├── 生成日报
  ├── 🚀 飞书三线通知（Track1采购群 + Track2排单群 + Track3老板群）
  ├── 审计
  └── 私聊通知排单员
```

问题：三线群通知在排单员确认之前就发出去了。采购群和老板群看到的可能是**排单员还没确认的中间态数据**。

### 目标流程

```
排单完成
  ├── 生成日报，写入飞书表（但暂不触发群通知）
  ├── 保存 report 到缓存（key=batch_id）
  ├── 审计
  └── 🚀 私聊通知排单员（卡片含"确认排单"按钮）

排单员审查 → 点击"确认排单"按钮
  ├── 调用 POST /confirm_schedule?batch_id=XXX
  ├── 从缓存加载 report
  ├── 🚀 发送 Track1（采购群）+ Track3（老板群）
  └── 缓存标记为"已确认"

如果排单员 30 分钟内未确认：
  └── 降级处理（可选，本期不做）
```

### 新增 API 端点

```
POST /confirm_schedule
  body: {"batch_id": "RUN-0621-001"}
  
返回:
  - 200: {"ok": true, "track1": true, "track3": true}
  - 404: {"ok": false, "error": "批次不存在或已过期"}
  - 409: {"ok": false, "error": "该批次已确认，不可重复发送"}
```

### 缓存策略

```
存储位置：全局 dict，key=batch_id，value={"report": {...}, "confirmed": False, "timestamp": float}
过期策略：锁定内存，最多保留 100 条，超限删除最早未确认的
清理时机：确认后标记 confirmed=True，30天后自动清理
```

### 按钮改造

排单员个人通知卡片中的"确认排单"按钮 URL 改为：
```
http://{SCHEDULER_HOST}:8000/confirm_schedule?batch_id=RUN-0621-001
```

> 注意：如果浏览器不能直接访问内网 8000 端口，需要改为飞书可访问的域名/公网地址。
> 备选方案：按钮指向一个飞书多维表格链接，飞书自动化规则检测到"确认"字段变更后回调 `/confirm_schedule`。

### 涉及代码改动

| 文件 | 函数/位置 | 改动 |
|------|---------|------|
| `scheduler_api.py` | L4335-4336 | 注释掉 `dispatch_schedule_notifications(report)`，改为 `_cache_report(batch_id, report)` |
| `scheduler_api.py` | L4367 | `_send_personal_notification` 的"确认排单"按钮 URL 改为 `confirm_schedule` 端点 |
| `scheduler_api.py` | 新增 | `_cache_report()` 函数 + `_report_cache` 全局 dict |
| `scheduler_api.py` | 新增 | `POST /confirm_schedule` 端点 |
| `scheduler_api.py` | `_send_personal_notification` | 紧缺物料展示改造（Top 5 + 总数） |

### Non-goals（本期不做）

- ❌ 不做 30 分钟超时自动降级
- ❌ 不做"已确认"状态回写到排单总表
- ❌ 不做"取消确认/撤回"功能
- ❌ 不做确认后的二次通知（如通知采购"排单已确认，请尽快更新交期"）

## 四、风险与缓解

| 风险 | 缓解 |
|------|------|
| 缓存内存泄漏（排单员长期不确认） | 最多保留 100 条，超限删除最早未确认的 |
| 服务重启后缓存丢失 | 确认后排单员可联系管理员手动触发通知 |
| 公网不可达（按钮 URL） | 备选：飞书多维表格自动化 + webhook 回调 |
| 多人点击确认 | 409 状态码 + 防重标记 |
