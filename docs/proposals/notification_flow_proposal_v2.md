## 二、改动 A：紧缺物料展示改造

### 当前

```
紧缺物料：全网行为管理-全网行为管理
```

只展示1个产品名称，无数量，无全貌。

### 目标

```
缺货物料：共 12 种

网络行为管理    缺 34 个（影响 5 个合同）
下一代防火墙    缺 23 个（影响 3 个合同）
交换机          缺 19 个（影响 2 个合同）
AI服务器        缺 15 个（影响 3 个合同）
存储设备        缺 8 个（影响 1 个合同）
...（最多展示 10 条）
+2 种详见排单总表
```

### 数据聚合逻辑

```
1. 筛选 summary[summary["整体状态"] == "缺货"]
2. 统计每种SKU的"受影响合同数"（从 summary.缺货SKU列表 解析）
3. 按受影响合同数降序排列
4. 展示前 10 条：SKU名称 + 受影响合同数
5. 超 10 条截断："+N 种详见排单总表"
```

> **口径说明**：此处展示"受影响合同数"（排单员视角：缺货的影响面），"绝对缺口数量"留给采购卡片展示。

### Non-goals

- ❌ 不展示"绝对缺口数量"（如"需求134，库存100，缺口34"）——这是采购卡片的内容
- ❌ 不翻译SKU编码为设备名称（直接用SKU编码）

## 三、改动 B：通知流程重构

### 3.1 当前流程（问题）

```
排单完成
  ├── 生成日报 → 写入飞书表
  ├── 🚀 三方群通知（采购群 + 老板群 + 排单群）  ← 排单员还没确认就发出去了
  ├── 审计
  └── 私聊排单员
```

**痛点**：采购和老板看到的是排单员未确认的中间态数据。

### 3.2 目标流程

```
Step 1：排单完成
  ├── 生成日报 → 写入飞书表（日报表天然持久化，无需额外缓存）
  ├── 审计
  ├── 🚀 私聊排单员（卡片含"确认排单"操作）
  └── 🚀 采购群发轻量消息"排单已完成，等待排单员确认中"

Step 2：排单员审查 → 点击"确认排单"
  ├── 飞书服务端回调 POST /feishu/card_callback
  ├── 从日报表按 batch_id 读 report（唯一数据源）
  ├── 🚀 发送 Track1（采购群）+ Track3（老板群）
  ├── 日报表回写：确认时间 + 确认人
  └── 排单员收到确认回执卡片"群通知已发送"

Step 3（异常）：排单员离线/请假
  └── 采购群和老板群有中间态消息作为上下文
  └── 排单员上线后处理积压确认（卡片不会消失）
  └── 如需紧急群发：管理员可调用 API 手动确认
```

### 3.3 状态机

```
                    ┌──────────────┐
                    │   待确认      │  排单完成，仅私聊发通知
                    │  (pending)    │
                    └───┬────┬─────┘
                        │    │
            排单员确认  │    │  管理员手动确认
                        │    │  POST /admin/confirm
                        ▼    ▼
                    ┌──────────────┐
                    │   已确认      │  日报表回写 confirmed_at / confirmed_by
                    │  (confirmed)  │
                    └───┬──────────┘
                        │
                触发群通知
               Track1 + Track3
                        │
               ┌────────┴────────┐
               ▼                 ▼
          ┌─────────┐      ┌──────────┐
          │ 推送成功  │      │ 部分失败   │  记录失败群名称
          │ (sent)   │      │ (partial) │  支持手动重发
          └─────────┘      └──────────┘
```

### 3.4 技术选型

| 决策点 | v1（错误） | v2（正确） | 理由 |
|--------|-----------|-----------|------|
| 报告存储 | 内存 dict | **飞书日报表** | report已写入日报表，天然持久化，重启不丢失 |
| 确认触发 | GET HTTP URL | **飞书卡片回调** | 按钮不能POST，飞书原生回调是唯一正确路径 |
| 确认人记录 | 不记录 | **日报表字段** | confirmed_at / confirmed_by，审计合规底线 |
| 防重机制 | 内存标记 | **日报表字段** | 持久化防重，重启不丢失 |
| 群配置 | 硬编码 Track1+Track3 | **代码中条件触发** | 简单场景无需过度抽象 |

### 3.5 飞书卡片回调按钮

排单员私聊卡片中的"确认排单"按钮改为飞书回调模式：

```json
{
  "tag": "button",
  "text": {"tag": "plain_text", "content": "确认排单"},
  "type": "primary",
  "value": {"action": "confirm_schedule", "batch_id": "RUN-0621-001"}
}
```

> 不再是 `url`，而是 `value`。点击后飞书服务端 POST 到应用后台配置的"消息卡片请求网址"。

### 3.6 新增 FastAPI 回调端点

```
POST /feishu/card_callback
  验证飞书签名（X-Lark-Signature）
  → 解析 action.value.batch_id
  → 从日报表读取 report（fetch_bitable_to_df + 过滤 batch_id）
  → dispatch_schedule_notifications(report)
  → 日报表回写 confirmed_at / confirmed_by
  → 返回卡片更新消息："已确认，群通知已发送"
```

### 3.7 日报表新增字段

在 `TABLE_ID_DAILY_REPORT` 飞书多维表格中手动添加：

| 字段名 | 类型 | 说明 |
|--------|------|------|
| 排单批次号 | 文本 | 已有 |
| 确认状态 | 单选 | "待确认"/"已确认"，默认"待确认" |
| 确认时间 | 文本 | ISO时间戳 |
| 确认人 | 文本 | 排单员 open_id 或姓名 |

### 3.8 涉及代码改动

| 文件 | 位置 | 改动 |
|------|------|------|
| `scheduler_api.py` | `_send_personal_notification` | 按钮从 `url` 改为 `value`（飞书回调模式）；紧缺物料展示改造 |
| `scheduler_api.py` | 新增 | `POST /feishu/card_callback` 端点（~35行） |
| `scheduler_api.py` | `run_scheduler` | dispatch_schedule_notifications 调用保留不动（当前流程已回退） |
| `ai_daily_agent.py` | `main()` | 注释掉 `execute_triple_track_dispatch(record)`，避免独立流程绕过确认 |
| 飞书应用后台 | 消息卡片请求网址 | 配置为 `http://{HOST}:8000/feishu/card_callback` |
| 飞书多维表格 | 日报表 | 手动添加3个字段 |

### 3.9 Non-goals

- ❌ 不做 30 分钟自动降级（用户明确要求手工确认）
- ❌ 不做"撤回已群发的通知"
- ❌ 不做排单员角色细分（多排单员场景）
- ❌ 不改造 ai_daily_agent.py 独立流程（仅注释掉群发调用）

## 四、改动 C：中间态通知

### 目标

排单完成后，在采购群发一条轻量消息：

```
今日排单已完成（61份合同），等待排单员确认后推送完整日报
```

### 实现

排单完成后，追加一次 webhook 调用发送 markdown 短消息到采购群 webhook。不暴露数据，仅通知状态。

## 六、风险与缓解

| 风险 | 缓解 |
|------|------|
| 飞书应用回调审批不通过 | 备选：按钮跳转到日报表某行，飞书自动化监测字段变更触发 webhook |
| 日报表读取失败 | 回调端点返回错误码，排单员看到"确认失败请重试"卡片 |
| Webhook 部分群发送失败 | 记录失败群名，排单员收到"部分群发送失败"提示 |
| ai_daily_agent.py 被独立触发 | 注释掉 main() 中的群发调用 |
| 排单员离线不确认 | 卡片不消失，上线后可补确认；管理员可调用 API 手动确认 |
