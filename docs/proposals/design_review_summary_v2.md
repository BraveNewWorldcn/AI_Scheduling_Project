## P0 致命问题（不改不能上线）

| # | 问题 | 来源 | 修订方案 |
|---|------|------|---------|
| 1 | **Card 3 markdown 表格在 JSON 1.0 不可用** — 四列指标表在当前卡片结构下无法渲染 | 技术专家 | 改用 `column_set` + `flex_mode:none` + 4列等宽，效果完全相同 |
| 2 | **色觉障碍用户无法区分红/黄/绿状态** — 8% 男性用户看不到差异 | UI Designer | 增加双通道编码：颜色 + 形状/文字标签（`<text_tag>`） |

| 设计元素 | 实现方式 | 限制 | 移动端 |

## 修订后的分阶段实施方案

### Phase 1（立即实施，零风险）

1. 去掉所有装饰型 emoji（🚨🧨💥⏳📊🔍📋📦✅），保留功能符号 ●○▲▼⚠
2. 用 `<text_tag>` 替代 ✅ 通过 / ⚠ 警告 标记
3. Card 1 增加"确认排单" primary 按钮
4. Card 2 增加"查看物料清单" secondary 按钮
5. 三张卡片底部统一加 `note` 时间戳
6. 为 `execute_triple_track_dispatch` 每个 Track 加独立 try-catch

### Phase 2（主体改造，需要测试环境验证）

7. Card 1：`column_set` 三格仪表盘 + 待确认合同展开 + 审计压缩为1行
8. Card 2：`column_set` 三格仪表盘 + Top 5 物料（含项目影响） + 动作清单
9. Card 3：`column_set` 四格仪表盘（替代 markdown 表格） + 核心发现1句话 + 风险清单
10. Card 3：每格增加目标基准对比（目标/当前/偏差）
11. 色觉无障碍双通道编码（颜色 + `<text_tag>` 标签）
12. Card 2 @认领改为具体责任人

### Phase 3（锦上添花，可选）

13. Card 1 增加确认时限"30分钟内完成确认"
14. Card 3 环比数据接入
15. 操作留痕（上次确认人/时间）

## 设计规范补丁

基于三路评审补充以下缺失规范：

### 灰阶系统
```
主文字  #1F2329
次文字  #646A73  
辅文字  #8F959E
分割线  #E5E6EB
背景    #FFFFFF
```

### 字号层级（飞书卡片 markdown 标签）
```
一级数字（仪表盘）→ **数字**（加粗大号，如 **61**）
标签（仪表盘下） → 普通文本
区块标题 → **标题：**
正文     → 普通文本
脚注     → note 组件
```

### 颜色使用规范（hex 精确值）
```
阻断/严重  #E03E3E  仅用于 P0 异常
警告/关注  #DFAB01  仅用于 P1 关注
正常/通过  #34C759  仅用于正常/达标
信息/操作  #3370FF  飞书默认蓝色
```

### 功能符号制（替代 emoji）
```
● / ○     状态指示（实心/空心圆）
▲ / ▼     趋势指示（三角箭头）
⚠          警告标记（仅 P0 使用）
每卡片 ≤2 个，同一区块 ≤1 个
```

---

**三路评审结论**：方案核心方向正确（仪表盘化 + 去装饰 + 差异化），但技术实现细节（markdown 表格→column_set）、业务字段（项目映射 + 目标基准）、可访问性（双通道编码）需要在落地前修正。修订后可直接进入 Phase 1+2 实施。
