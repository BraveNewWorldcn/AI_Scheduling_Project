# 面试话术：AI 排单引擎项目

> 目标岗：苏州制造业智能仓储数据岗（博世/友达光电/中际旭创）  
> 时长控制：3分钟主叙述 + 2分钟演示 + 自由问答

---

## 一、开场（30秒，一句话把面试官抓住）

> "我主导设计了一套 AI 排单引擎，用 Multi-Agent 架构把供应链排单从 3-5 天压缩到 1 小时。关键是，我把它架在了企业已有的飞书平台上，没有额外增加任何服务器成本。"

**面试官听到的关键词**：Multi-Agent 架构、10倍效率提升、零成本部署。三个词全部击中制造业数据岗的需求。

---

## 二、问题切入（你为什么做这个？）

> "传统排单员每天面对几十份合同，手动匹配库存、确认交期、通知采购。一条漏排可能造成产线停线。我们公司的排单员每天花 3-4 小时核对，财务对账更是要 3-5 天才能出一个结果。"

不要只说"效率低"，要说"产线停线"——制造业面试官对这个词有生理反应。

---

## 三、架构决策（你的技术判断力）

### 为什么用 Multi-Agent 而不是单个大模型？

> "我选了 Multi-Agent 而不是单个大模型，因为排单不是单一任务——物料匹配是规则推理、AI 分析是语义理解、卡片推送是格式化输出。一个模型做所有事情效果会差很多。我拆成三个 Agent 各司其职。"

### 为什么纯飞书方案而不是自己搭服务器？

> "系统需要让排单员、采购、领导层三类人分别看到不同的信息。重新开发一个前端 + 后端 + 推送系统，光是账号体系就要搞一个月。飞书本身就是他们的工作入口，我只是在现有平台上做增量——卡片通知、多维表格存数据、妙搭托管确认面板。零服务器，零运维。"

**这段的价值**：面试官看到你不只是会写代码，你会做技术选型和成本权衡。

## 五、通知系统设计（展示架构能力）

> "通知系统的难点在于：排单结果出来后，三类人需要不同的信息。排单员要看到每一份合同的状态、采购要看到缺货物料列表、老板只要看交付率和大盘健康度。"

> "我设计了三线异步推送：排单完成后先私聊排单员确认，确认后才群发给采购和老板。中间态只发一条轻量提示到采购群告知'已排单，等待排单员确认'。这个流程设计避免了错误排单直接广播到全公司。"

> "老板卡片我做了双通道色彩编码——绿色正常、橙色关注、红色告警，同时配上文字标签，色盲也能看懂。关注项上限 3 条，防止信息过载制造焦虑。"

## 八、面试官可能追问 & 你的回答

**Q: 为什么不用传统数据库？**
A: "供应链数据已经在飞书多维表格里了，再建一套数据库会有数据同步问题。我选择直接读飞书数据源，保持单一事实来源。"

**Q: 遇到什么技术难点？**
A: "飞书卡片 JSON 协议的限制——按钮不能 POST 只能 GET、markdown 表格不渲染、移动端和桌面端布局差异。我把按钮改为原生回调 + 降级链接，卡片改用 column_set 组件做仪表盘布局，用 text_tag 替代 emoji 做状态标识。"

**Q: 这个系统的 P0 风险是什么？**
A: "当前最需要关注的是 Token 安全、缓存一致性和状态碎片化。我已经排查并列入整改计划。但这个系统跑在飞书平台内，天然的权限隔离降低了风险——只有授权用户才能访问多维表格和卡片。"
